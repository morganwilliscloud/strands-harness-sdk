As conversations grow, your agent's context window fills with messages, tool results, and system prompts. Without management, this leads to token limit errors, degraded performance, and loss of relevant information.

The SDK ships context management configurations that work out of the box. Pick a mode and the SDK wires up the pieces with tuned defaults. You can drop down to explicit strategy configuration when you need fine-grained control.

:::note[Migration note]
The `SummarizingConversationManager`, `ContextOffloader`, and `conversation_manager` are superseded by the `ContextManager` strategy API described on this page. They continue to work for now. See [Migrating from the legacy API](#migrating-from-the-legacy-api) if you want to move over.
:::

## Automatic context management

For most agents, pass <Syntax py='context_manager="auto"' ts='contextManager: "auto"' /> and the SDK wires up context management with no further configuration:

The `"auto"` configuration combines two strategies whose defaults scored highest across [ContextBench](https://arxiv.org/abs/2602.05892) evaluations. On real code investigation tasks, these defaults dropped costs 55% while accuracy improved from 68% to 98%. See the [benchmark writeup](https://strandsagents.com/blog/reduced-cost-better-isolation-more-resilience/) for details.

- **Large tool result offloading**: tool results over 2,500 tokens are replaced with a 1,000-token preview. The full content is stored in the stash and the agent gets a `retrieve_context` tool to fetch it on demand.
- **Proactive summarization**: when the context window reaches 85% utilization, older messages are summarized and replaced with a compact summary block.

## Agentic context management

:::caution[Experimental]
Agentic context management is experimental and may change in future
versions. Use with caution in production environments.
:::

Pass <Syntax py='context_manager="agentic"' ts='contextManager: "agentic"' /> and the model manages its own working memory: it sees how full the context window is and decides when to compress, what to compress, and what to protect.

<Tabs>
<Tab label="Python">

```python

agent = Agent(context_manager="agentic")
```

The model is better positioned than a fixed threshold to know which messages still matter. A coding agent can drop a stale file it already edited while pinning the failing test it is working toward. A threshold cannot tell the difference; it compresses by age. Agentic mode trades tokens for that judgment.

**Token-usage telemetry.** Before each model call, the SDK appends a status block to the latest message:

```
<context-status>
<used>50,000 / 200,000 tokens (25.0%)</used>
<remaining>~150,000 tokens</remaining>
</context-status>
```

**Three tools the model can call:**

- `summarize_context` folds older messages into a model-written summary. The model chooses how many recent messages to keep verbatim and what to target.
- `truncate_context` drops older messages outright. The model chooses how much history to keep.
- `pin_context` marks messages that must survive any compression. Pinned messages are never evicted.

Use `"auto"` for most agents. It manages context in the background with no model involvement. Reach for `"agentic"` when you want the model to judge relevance per message rather than compress on a fixed threshold.

## Explicit strategy configuration

:::caution[Experimental]
The `ContextManager` strategy API is experimental and may change in future versions.
:::

When you need fine-grained control, pass a `ContextManager` instance directly. Strategies are applied in order where each one sees the output of the previous.

<Tabs>
<Tab label="Python">

```python
# NOTE: will move to `from strands import ContextManager, Offload` in a future release
from strands.experimental.context_manager import ContextManager, Offload
from strands.storage import LocalFileStorage

agent = Agent(
    context_manager=ContextManager(
        strategies=[
            # Offload large tool results; keep a 500-token preview in context
            Offload.truncate(
                "tool_results",
                {"preview_tokens": 500},
            ).when(threshold=2500),
            # Summarize older messages when the window reaches 85% utilization
            Offload.summarize("*").when(utilization=0.85, preserve_recent=2),
        ],
        # Stash keeps originals and registers a retrieve_context tool.
        # Omit for in-memory, or pass LocalFileStorage/S3Storage for durability.
        stash={
            "storage": LocalFileStorage("./artifacts/"),
        },
    ),
)
```

### Strategy targets

The first argument to `Offload.*` controls what content the strategy considers:

| Target | Matches |
|---|---|
| `"*"` | All messages and tool results |
| `"tool_results"` | Successful tool result blocks |
| `"tool_result_errors"` | Errored tool results |
| `"assistant_text"` | Assistant text turns |
| `"user_text"` | User text turns |
| `["bash", "read_file"]` | Results from specific named tools |
| `["!read_file"]` | Everything except `read_file` results |

### Strategy conditions

`.when(...)` sets when the strategy fires:

| Condition | Meaning |
|---|---|
| `threshold=N` | Fire when an individual block exceeds N tokens |
| `utilization=0.85` | Fire when the context window is at least 85% full |
| `preserve_recent=N` | Leave the N most recent matching messages untouched |

### Named presets (TypeScript)

### Custom summarization model

Summarizing history doesn't require your most capable model. Pass a cheaper one via the strategy config:

<Tabs>
<Tab label="Python">

```python
from strands.experimental.context_manager import ContextManager, Offload
from strands.models import BedrockModel

agent = Agent(
    context_manager=ContextManager(
        strategies=[
            Offload.summarize(
                "*",
                {
                    "model": BedrockModel(model_id="us.amazon.nova-lite-v1:0"),
                    "system_prompt": "Summarize preserving tool outputs, errors, and IDs.",
                },
            ).when(utilization=0.85, preserve_recent=2),
        ],
        stash=False,
    ),
)
```

## Storage backends

Both `"auto"` mode and the explicit `ContextManager` use in-memory storage by default. Content does not persist across process restarts. For durable stash storage:

<Tabs>
<Tab label="Python">

```python
from strands.storage import LocalFileStorage, S3Storage

# Local filesystem
stash = {"storage": LocalFileStorage("./artifacts/")}

# S3, uses ambient AWS credentials
stash = {"storage": S3Storage("my-bucket", prefix="agent-stash/")}
```

## Limitations

**Stateful models**: Setting <Syntax py="context_manager" ts="contextManager" /> with a stateful model raises a <Syntax py="ValueError" ts="Error" />. Stateful models manage conversation state server-side.

## Migrating from the legacy API

If you are currently using `SummarizingConversationManager`, `ContextOffloader`, or the `conversation_manager` param, the table below shows the equivalents in the new API:

| Legacy | New |
|---|---|
| `SummarizingConversationManager(summary_ratio=0.3)` | `Offload.summarize("*").when(utilization=0.85, preserve_recent=2)` |
| `ContextOffloader(max_result_tokens=2500, preview_tokens=500)` | `Offload.truncate("tool_results", {"preview_tokens": 500}).when(threshold=2500)` |
| `conversation_manager=SlidingWindowConversationManager(window_size=30)` | `Offload.drop("*").when(preserve_recent=30)` |
| `context_manager="auto"` | unchanged |
